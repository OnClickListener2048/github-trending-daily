  • 统一接管本机已登录的多种 AI 编程代理：Claude Code、Codex、Cursor、Grok Build、OpenCode、Antigravity、fx

  • 覆盖主流包管理器的桌面端分发：winget、scoop、Homebrew、.deb、AUR（含 nightly 频道）、nixpkgs

#6shiyu-coder/Kronos

首个开源金融K线基础模型，在45+全球交易所数据上预训练，提供预测与微调能力。

Kronos 是一个专门为金融市场「语言」——K线序列——打造的开源基础模型系列，采用 decoder-only 架构，在超过 45 个全球交易所的数据上预训练。它不像通用时间序列模型那样忽视金融数据的高噪声特性，而是用两阶段框架解决问题：先用专用 tokenizer 把连续的多维 OHLCV 数据量化成分层离散 token，再让自回归 Transformer 在这些 token 上预训练，从而用一个统一模型覆盖多种量化任务。使用上非常直接：从 Hugging Face 加载 tokenizer 与模型，实例化 KronosPredictor，它自动完成预处理、归一化、预测和反归一化，几行代码即可从原始行情得到预测结果。模型提供 mini、small、base 等多个规格，按算力和场景选择；官方还放出了微调脚本，方便适配自己的任务。

  • 首个面向金融 K 线（OHLCV）的开源基础模型，预训练覆盖 45+ 全球交易所
  • 两阶段框架：专用 tokenizer 将多维 K 线量化为分层离散 token，再由自回归 Transformer 建模
  • KronosPredictor 一站式封装预处理、归一化、预测与反归一化，几行代码出结果
  • Model Zoo 提供多规格预训练权重：Kronos-mini（4.1M）、small（24.7M）、base（102.3M），均可从 Hugging Face 直接加载
  • 兼容不同上下文长度：mini 支持 2048，small/base 为 512，超长输入由 Predictor 自动截断
  • 提供微调脚本，可将模型适配到自定义量化任务

👥 适合谁：量化研究员、金融时序建模开发者，以及想把基础模型用于行情预测的算法工程师。

为并行 AI 代理工作流设计的 Git worktree 管理 CLI，让 worktree 用起来像分支一样简单

agentsclaude-codecodexdeveloper-tools
📖 详细介绍

Worktrunk 是一个用 Rust 写的命令行工具，封装了 Git 原生的 worktree 功能。它解决的问题很具体：当你同时跑 5~10 个 Claude Code、Codex 这类 AI 代理时，每个代理需要独立的工作目录才不会互相踩改动，而 git worktree 的原始体验很笨拙——建一个 worktree 要把分支名敲三遍（git worktree add -b feat ../repo.feat 再 cd 过去），清理又要回到主仓库执行 remove 和 branch -d。Worktrunk 把 worktree 按分支名寻址，路径由可配置的模板自动推算，于是切换、创建、删除、列出都变成一条短命令，比如 wt switch feat、wt switch -c -x claude feat（建 worktree 并直接拉起 Claude）、wt remove、wt list。命令既接受分支名，也接受该 worktree 的路径，日常操作基本不用再记目录。

  • 三个核心命令：wt switch 切换、wt remove 清理（连分支一起删）、wt list 列出所有 worktree 及其状态，而不只是路径
  • 一条命令创建工作树并启动代理：wt switch -c -x claude feat，替代 git worktree add + cd + claude 三步
  • 按分支名寻址 worktree，路径由可配置的模板自动计算，命令同时兼容传入分支名或 worktree 路径
  • Hooks 机制：在创建、pre-merge 等生命周期节点自动执行命令，把本地重复流程固化下来
  • copy-on-write 构建缓存，避免每个并行 worktree 都重新构建一遍依赖
  • 面向“同时管理多个并行改动”的一批体验优化，减少在多个 worktree 之间来回操作的心智负担

👥 适合谁：需要同时跑多个 AI 编码代理、或经常并行开发多条分支的开发者

  • 按业务目标编排 AI 代理团队，而不是逐个管理 PR
  • 支持 OpenClaw、Claude Code、Codex、Cursor、Gemini CLI、OpenCode、Pi、Hermes、Grok、Kimi 等多种代理与执行框架

  • 提供组织架构、角色分工与任务、技能、权限、历史的集中管理
  • 内置预算与成本追踪，按团队和代理监控花费
  • 治理与审批流程：先审核策略、设定预算，再批准运行

nanochat 是一个极简、可随意改动的 LLM 训练实验框架，覆盖分词、预训练、微调、评估、推理五大环节，专为单台 GPU 节点设计。它要回答的问题是：从零训一个大模型到底要写多少代码、花多少钱。答案是——只需设定一个复杂度参数 --depth（层数，depth 26 大致对应 GPT-2 能力），宽度、头数、学习率、训练时长、权重衰减等超参数都会按最优方式自动推导。跑 runs/speedrun.sh 即可在 8XH100 上约两小时、约 48 美元（spot 实例可低至约 15 美元）训出 GPT-2 级模型，再用 python -m scripts.chat_cli 和它对话。

  • 全流程覆盖：分词、预训练、微调、评估、推理一站式，代码保持极简、易读易改。
  • 单参数控制规模：只调 --depth，其余超参数自动按 compute-optimal 推导，可成系列地训练一整条模型线。
  • 一键复现 GPT-2：runs/speedrun.sh 在 8XH100 上约两小时、约 48 美元训出 GPT-2 能力模型。

Heretic 是一个让你像大公司一样"改造"而不只是"运行"语言模型的工具。它不做昂贵的训练，而是用一组数学方法，基于对照示例提示和评分器来引导模型行为。默认动作是去除审查、抑制拒答，也提供减少废话、减少幽默、降低谄媚、调整情绪倾向等现成配置。用法极简：装好 PyTorch 环境后 pip install -U heretic-llm，再执行 heretic 模型名即可，在 RTX 3090 上处理一个 4B 模型约需 30-40 分钟；跑完可以选择保存模型、上传 Hugging Face、直接对话测试或跑基准评测。

  • 去除审查、抑制拒答：默认配置即执行，开箱即用
  • 多种现成行为配置：减少 slop 废话、减少幽默、降低谄媚、调整情绪倾向
  • 免训练改造：用数学方法引导行为，不需要理解模型内部原理，也不需要昂贵算力
  • 支持大多数稠密模型，包括不少多模态模型、多种 MoE 架构和现代混合模型

  • 可扩展的 scorer 插件机制：继承 Scorer 接口写 get_score 就能自定义优化目标
