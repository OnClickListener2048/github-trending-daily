#1pingdotgg/t3code

统一管控本机多种 AI 编程代理的跨平台控制台，覆盖手机、网页与桌面。

T3 Code 是一个“agent harness 控制面”：它本身不提供模型，而是接管你电脑上已经装好并登录的 Claude Code、Codex、Cursor、Grok Build、OpenCode、Antigravity 和 fx，把它们的会话统一到一个界面里操作。官方说得很直白——不卖任何东西，只是嫌现有 Codex 桌面端、Conductor、Claude Desktop、Cursor Glass 都不够快、不够远程、不够开放，于是自己造了一个，并且保证你随时能 fork 出走。用法很简单：先在本机装好并登录至少一个 provider，然后执行 curl 安装脚本或 npx t3@latest 启动服务并打开本地 Web 应用，也可以从 GitHub Releases、Homebrew、winget、scoop、AUR、nixpkgs 安装桌面版；t3 service install 可让它常驻后台，t3 update 负责升级。

  • 一处接管多家代理：Claude Code、Codex、Cursor、Grok Build、OpenCode、Antigravity、fx 只要本机装好并登录，就能被统一控制
  • 多端同源：iOS、Android 原生应用、app.t3.codes 网页端和基于 Electron 的桌面端共享同一套服务
  • 远程访问：可从手机或另一台机器连回自己电脑上的 agent 会话，不必守在桌前
  • 命令行一体化：curl/irm 一行装好，t3 启动服务，t3 service install 常驻后台，t3 update 升级，npx t3@latest 免安装试用
  • 通过 MCP 与外部 agent 互通：Claude Code、Codex、ChatGPT 等可以反过来连接 T3 Code
  • 开发体验细节：权限模式、键盘快捷键、项目设置、外观偏好，以及源码管理集成和多账号（Codex、Claude）支持

👥 适合谁：已在本机使用多个 AI 编程 agent、希望统一管理并能远程操控的开发者。

#3thedotmack/claude-mem

为 AI 编程 Agent 提供跨会话持久记忆，自动记录、压缩并回注上下文。

claude-mem 是一个面向 Claude Code 等 AI 编程 Agent 的持久记忆压缩系统。它解决的是 Agent 每次会话结束后就忘记此前工作的麻烦：会话期间，它自动捕获 Agent 的工具使用观察记录，用 AI 将其压缩成语义摘要并保存下来，然后在之后的会话中把相关上下文注入回去。这样即使中途断开重连或开启新会话，Agent 依然记得这个项目做过什么、怎么做的。安装很轻量，一条 npx claude-mem install --ide <你的 IDE/Agent> 命令即可接入，支持 Claude Code、Codex、Gemini、Copilot、OpenCode 等多种宿主，提供 MCP 搜索工具来检索历史记忆，还带有配置项与故障排查文档，并附有多语言 README。

  • 自动捕获：会话过程中持续记录 Agent 的工具使用观察，不需要手动保存
  • AI 压缩：把冗长的会话记录压缩成语义摘要，避免把原始日志全部写入上下文窗口
  • 上下文回注：在后续会话中自动注入相关记忆，让 Agent 保持项目知识的连续性
  • MCP 搜索工具：通过 MCP 接口在历史记忆中检索，按需取用过去的上下文
  • 多 Agent 兼容：除 Claude Code 外，还支持 Codex、Gemini、Copilot、OpenCode、Hermes、OpenClaw 等宿主
  • 一条 npx 命令安装，并支持配置与故障排查文档

👥 适合谁：长期用 Claude Code 等 AI 编程 Agent 做项目的开发者。

#5mattpocock/skills

  • /grill-me 和 /grill-with-docs：动手前先让 Agent 反过来“拷问”你，把需求问透，解决最常见的“Agent 做的不是我想要的”对齐失败
  • 共享语言/术语表机制：给 Agent 一份项目行话对照文档，让它不再用 20 个词说 1 个词的事，输出明显更简短
  • 多 Agent 覆盖安装：Claude Code、Codex、GitHub Copilot（CLI 与 VS Code）、Gemini CLI，以及通过 npx skills 支持 cursor、opencode、devin、windsurf、amp、pi 等
  • 两种更新模式可选：插件方式自动更新，skills.sh 方式把可编辑文件拷进项目由你手动维护、随手魔改
  • /setup-matt-pocock-skills 一次性初始化：选定 issue tracker（GitHub、GitLab、本地文件或自定义）、triage 用的标签、文档保存位置
  • 技能按 engineering 与 productivity 分类，配合 /triage 使用你设定的标签做工单分诊

👥 适合谁：日常用 Claude Code、Codex 等 Agent 写真实项目的工程师，尤其是受够重型流程框架、想保留控制权的人。

D4Vinci/Scrapling

Scrapling 是一个 Python 网页抓取框架，把快速请求、隐身浏览器、解析和并发爬虫整合在一起。

aiai-scrapingautomationcrawler
📖 详细介绍

抓取现代网页通常要同时应付静态 HTML、JavaScript 渲染、反爬拦截和并发调度，很多人只能把 requests、Playwright、解析库和爬虫框架拼在一起用。Scrapling 把这些能力收进一个 Python 库：既能发快速 HTTP 请求，也能用隐身浏览器渲染页面、与网站交互，并拿到页面背后 API 调用返回的数据；解析部分提供多种选择器，可直接从响应中提取字段。往上还能构建正式爬虫，支持可复用会话、代理轮换、自动重试、暂停与恢复以及内置数据导出。除了写 Python 代码，也可以从终端 CLI 使用，或通过 MCP server 和 Agent Skill 让 AI agent 直接调用。

  • 快速 HTTP 请求抓取静态页面，并可用隐身浏览器渲染 JavaScript、与页面交互
  • 解析能力：提供多种选择方式，从 HTML 响应中精准提取所需字段
  • 可获取页面背后 API 调用返回的数据，而不只是渲染后的 DOM
  • 并发爬虫：支持可复用会话、代理轮换、自动重试、暂停与恢复
  • 内置数据导出，可把整站内容整理成干净的 Markdown 等格式
  • 三种使用入口：Python 库、终端 CLI，以及面向 AI agent 的 MCP server 与 Agent Skill

👥 适合谁：需要从单次请求到整站爬取的 Python 开发者、数据采集工程师，以及想让 AI agent 直接抓网页的人。

Hyprland 是一个完全独立实现的 Wayland 合成器，采用动态平铺窗口管理。它要解决的核心矛盾是：平铺窗口管理器往往性能好但界面朴素，而 Hyprland 提供渐变边框、多种模糊、发光、阴影和自定义贝塞尔/弹簧曲线动画等视觉效果，同时不牺牲可配置性和性能。它不依赖 wlroots、kwin 或 mutter，从底层自行实现。使用方式是先按官方 Wiki 安装并完成 Quick Start，然后在配置文件中定义键位、窗口规则、布局与动画；保存配置后立即生效，无需重启。日常操作通过全局快捷键驱动，并可用 Socket IPC 与脚本或状态栏联动。

  • 丰富的视觉特效：渐变边框、多种模糊、动画、发光与阴影
  • 强大的插件系统并内置插件管理器，可自行扩展功能
  • 多种布局：Dwindle、Scrolling、Master、Monocle，支持 Lua 自定义布局与按工作区指定布局
  • 特殊工作区（scratchpad）与窗口组（Tabbed 标签模式）
  • 基于 Socket 的 IPC，以及可转发给应用的全局快捷键
  • 窗口、显示器、图层规则，配置保存后即时重载

shiyu-coder/Kronos

首个开源金融K线基础模型，基于45+全球交易所数据预训练

📖 详细介绍

Kronos 是首个专门为金融市场「语言」——K线（OHLCV）序列打造的开源基础模型。通用时序模型往往难以应对金融数据的高噪声特性，Kronos 采用两阶段框架解决这个问题：先用专用 tokenizer 把连续的多维K线数据量化成分层离散 token，再用大规模自回归 Transformer 在这些 token 上预训练，从而用一个统一模型支撑多种量化任务。使用时只需从 Hugging Face 加载 tokenizer 和模型，实例化 KronosPredictor，它就会自动完成预处理、归一化、预测与反归一化，几行代码即可从原始行情得到预测结果。

  • 首个面向金融K线的开源基础模型，预训练数据来自 45+ 家全球交易所
  • 两阶段框架：专用 tokenizer 将连续 OHLCV 量化为分层离散 token，再由自回归 Transformer 建模
  • 提供 Kronos-mini/small/base/large 四档模型（4.1M~499.2M 参数），对应不同算力与精度需求，权重托管于 Hugging Face
  • KronosPredictor 封装预处理、归一化、预测、反归一化全流程，数行代码完成预测；超出上下文长度会自动截断
  • 官方提供微调脚本，可将 Kronos 适配到自己的量化任务与数据集上
  • 在线 Live Demo 可视化 BTC/USDT 未来 24 小时预测结果，另附 arXiv 论文与 AAAI 2026 接收记录

👥 适合谁：量化研究员、金融时序建模开发者，以及想把基础模型能力迁移到自有行情数据的团队

JustVugg/colibri

纯 C 编写的 MoE 推理引擎，专家按需从磁盘流式读取，让普通电脑也能跑数百亿参数大模型。

📖 详细介绍

colibri 是纯 C 编写的推理引擎，目标是让普通电脑也能运行超大开源的 MoE 模型。MoE 每生成一个 token 只用到一小部分专家，colibri 就让这部分专家常驻内存，其余专家留在磁盘上按需读取，因此几百亿参数的模型在 8GB 内存起步的机器上也能跑起来。它内置十三个引擎，覆盖 GLM-5.2/5.3、Kimi K3、DeepSeek V4 Flash、Qwen3.6 等语言模型，另有图像模型和决策模型；它能直接读取现成的 GGUF 文件，可用 CPU 运行，也可走 Vulkan 或 CUDA。运行 start-here 脚本后，它会检查机器、推荐装得下的模型、下载并启动服务，随后在浏览器打开面板，并对外提供 OpenAI、Anthropic 兼容接口。

  • 专家流式加载：只把每个 token 实际用到的专家留在内存，其余专家从磁盘按需读取；比如 744B 的 GLM-5.2，常驻内存约 9.9 GB
  • 十三个引擎开箱即用：GLM-5.2/5.3（兼跑 Mistral-Large-4）、GLM-5.3-Flash、Inkling、Kimi K3、DeepSeek V4 与 V4.1 Flash、MiMo-V2.6 Flash（含 Pro）、Qwen3.8-Flash-Next、Qwen3.6（兼跑 Qwen3-Coder、稠密 Qwen3.8-27B、Flint、Muse Spark Open、LFM3-VL）、OLMoE，外加图像模型 Qwen-Image-2.1 与 Laya、GLiNER2.5-Decide 决策模型
  • 纯 C 实现、零依赖、不需要显卡；可选 Vulkan（任意 GPU）与 CUDA（NVIDIA）后端，安装脚本只在 GPU 确实更快时才为它编译
  • 直接加载社区已发布的 GGUF 文件，无需转换格式，在 CPU 上按原样读取运行
  • 一步安装：自动探测内存、空闲磁盘、CPU 与 GPU，推荐放得下的模型（常驻部分与最小专家缓存必须装进内存），有编译器就本地构建，否则下载预编译版，模型下载支持中断续传
  • 跑起来即是一个本地服务：自带浏览器面板，并同时提供 OpenAI（/v1）与 Anthropic 兼容接口，其他应用可以直接接上

👥 适合谁：手里只有普通电脑、内存 8–16 GB、没有高端显卡，却想在本地跑大 MoE 模型的开发者和爱好者。

用 Rust 写的 Git worktree 管理命令行工具，专为并行运行 AI 编程代理设计

agentsclaude-codecodexdeveloper-tools
📖 详细介绍

Worktrunk 把 Git worktree 操作简化到和切换分支一样顺手。Git 原生 worktree 能为每个 AI 代理提供独立工作目录，避免改动互相干扰，但创建时连分支名都要敲三遍：git worktree add -b feat ../repo.feat 再 cd 过去。Worktrunk 用分支名寻址 worktree，路径按可配置模板自动生成，核心就三个命令：wt switch feat 切换、wt switch -c -x claude feat 创建并直接启动 Claude、wt remove 清理，还有 wt list 带状态列出所有工作树。除了这三个命令，它还提供 hooks（在 create、pre-merge 等时机自动跑命令）以及写时复制（copy-on-write）的构建缓存，帮你在同时推进多个并行改动时少干重复活。

  • 核心命令 wt switch 按分支名切换 worktree，路径自动按模板计算
  • wt switch -c -x claude 一步完成创建 worktree、建分支并启动 AI 代理
  • wt remove 一条命令删除工作树并清理对应分支，替代多步 git 操作
  • wt list 列出所有 worktree 并附带状态信息，而非只有路径
  • Hooks 在创建等时机自动执行命令，把本地流程串起来
  • 支持写时复制（copy-on-write）构建缓存，多个并行工作树共享构建产物

👥 适合谁：需要并行跑 5-10 个以上 AI 编程代理、或经常同时维护多个分支改动的开发者

Paperclip 是一个 TypeScript 写的开源应用（Node.js 服务端 + React 界面），用来编排一整支 AI 智能体团队去完成业务目标。它解决的问题不是「怎么让单个 agent 更聪明」，而是「一群人（agent）怎么协作、谁负责什么、花了多少钱」。用法很直白：先定义一个业务目标（比如把某产品做到 100 万美元 MRR），再从任意供应商里「招聘」CEO、CTO、工程师、设计、市场等 bot 组成团队，审完策略、设好预算后开跑，在同一个面板里追踪任务进度和成本。界面看起来像任务管理器，底下藏的是组织架构、预算、治理、目标对齐和 agent 协调。官方一句话概括它的定位：如果 OpenClaw 是员工，Paperclip 就是公司。

  • 按业务目标而非 PR 组织工作：定义目标 → 组建团队 → 审批并运行，三步启动
  • 自带 agent：支持 OpenClaw、Claude Code、Codex、Cursor + Cloud、Gemini CLI、OpenCode、Pi、Hermes + Gateway、Grok Build、Kimi Code 等，只要能接收 heartbeat 就能「入职」
  • 每个 agent 可单独选择模型和 harness，同时把团队的任务、技能、权限、历史统一沉淀在一处
  • 组织架构与治理：角色分工、权限控制、策略审批，开会之前先把规矩定好
  • 预算与成本追踪：给团队设预算，在面板里实时看花的钱和产出
  • 可扩展名册：自定义进程、HTTP 端点、外部 adapter 包都能接入，不局限于内置列表

👥 适合谁：想让多个 AI agent 组成团队跑真实业务的开发者和小团队，尤其是已经在混用 Claude Code、Codex、Cursor 等多种 agent 的人

📖 详细介绍

nanochat 是一个极简的 LLM 训练实验框架：在单节点 GPU 上跑通 tokenization、预训练、微调、评估、推理全流程，代码量小、便于修改。它要回答的是“训练大模型到底有多贵”——2019 年花约 4.3 万美元才训出的 GPT-2 能力，现在约 48 美元、两小时即可复现，用 spot 实例约 15 美元。用法直接：uv sync 装依赖，跑 bash runs/speedrun.sh 训练，再用 python -m scripts.chat_cli 和模型聊天。

  • 覆盖 tokenization、预训练、微调、评估、推理全部主要阶段，单文件 runs/speedrun.sh 就是完整参考流程
  • 只用一个 --depth 复杂度旋钮（层数）就能定义模型规模，宽度、头数、学习率、训练步数、weight decay 等超参全部自动按最优方式推导
  • 一条命令复现 GPT-2 能力模型：8XH100 约 1.5~2 小时、约 48 美元，spot 实例约 15 美元，训完直接在 CLI 里对话
  • 维护“Time-to-GPT-2”速度榜，以 DCLM CORE 分数对标 GPT-2（0.256525），记录社区把训练时间从 168 小时压到 1.65 小时的每一轮改进
  • 适配多种硬件：8XA100 也能跑，去掉 torchrun 后单卡自动切梯度累积、结果几乎一致（只是慢 8 倍），也支持 CPU/MPS
  • 依赖用 uv 管理，区分 gpu / cpu extra 和 dev group，开发调试所需工具一并装好

👥 适合谁：想亲手训练并吃透 LLM 全流程的研究者、学生和工程师，手上有 H100/A100 即可上手

abliterationanti-censorshipanticensorshipcensorship
📖 详细介绍

Heretic 是一个免训练的语言模型改造工具，让你无需投入大模型训练，就能像拥有大算力的公司那样去「改造」而非只是「运行」模型。它通过对比示例提示与对应的评分器，用一组数学方法直接调整模型行为：默认配置就是移除拒答、去除审查，也提供压制废话、降低幽默、减少谄媚、调节情绪倾向等现成配置文件。使用方式很轻：装好 PyTorch 2.6+ 后执行 pip install -U heretic-llm，再运行 heretic 加模型名即可；例如在 RTX 3090 上处理 Qwen3-4B 约需 30–40 分钟。跑完后可以选择保存模型、上传到 Hugging Face、直接对话测试，或运行基准评测。它还支持 bitsandbytes 的 4-bit 量化，把显存需求压到与运行量化版模型相当的水平。

  • 默认执行拒答抑制（移除审查），开箱即用
  • 内置多套行为配置：压制废话、减少幽默、降低谄媚、调整情绪倾向，也可自写配置
  • 基于对比提示与评分器的免训练行为引导，无需了解模型内部原理
  • 评分器插件机制：继承 Scorer 并实现 get_score 即可自定义优化目标，默认按拒答率与 KL 散度打分
  • 支持大多数 dense 模型、多模态模型、多种 MoE 架构与现代混合模型
  • 运行开始时自动做系统基准测试以确定最优批大小，支持 bitsandbytes 4-bit 量化降低显存占用

👥 适合谁：想在本地或自有硬件上改造开源模型、调整模型行为偏好的开发者与本地部署玩家
